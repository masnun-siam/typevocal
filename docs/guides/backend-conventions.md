# Backend conventions

Rules for changing `src-tauri/` (Rust + Tauri 2), confirmed against the code; paths are repo-relative.

## Module layout

| Where                              | What goes there                                                                                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src-tauri/src/lib.rs`             | `mod` list, logging setup, `run()`: manager construction + `.manage(...)`, `collect_commands!`/`collect_events!`, plugins, `setup`                   |
| `src-tauri/src/main.rs`            | Entry only; checks `is_worker_invocation()` first (line 29), then calls into the lib crate (`typevocal_app_lib`)                                     |
| `src-tauri/src/managers/`          | Stateful business logic: `audio`, `model`, `transcription`, `history` (+ `model_capabilities`, `gguf_meta`); sub-modules like `model/download.rs`    |
| `src-tauri/src/commands/`          | Thin `#[tauri::command]` handlers grouped by area (`audio`, `history`, `models`, `transcription`, misc in `mod.rs`); logic stays in managers         |
| `src-tauri/src/shortcut/`          | Global shortcut registration and handling; two backends (`tauri_impl.rs`, `handy_keys.rs`) behind `mod.rs`; its commands live in `mod.rs`            |
| `src-tauri/src/audio_toolkit/`     | Low-level audio (cpal devices, recorder, resampler, VAD, text post-processing). No Tauri types; `bin/cli.rs` is commented out in `Cargo.toml`        |
| `src-tauri/src/engine_supervisor/` | Parent side (`supervisor.rs`), child side (`worker.rs`), framed `protocol.rs`                                                                        |
| `src-tauri/src/catalog/`           | Bundled offline model catalog (`catalog.json` embedded via `once_cell::Lazy`); produces `ModelDescriptor`s for `managers/model.rs`                   |
| `src-tauri/src/paste_tx/`          | Receipt-sequenced clipboard paste; `macos.rs` / `windows.rs` selected by `cfg` in `mod.rs`                                                           |
| `src-tauri/src/helpers/`           | Tiny platform helpers (only `clamshell.rs` today); its command `is_laptop` is registered in `lib.rs`                                                 |
| Top-level `src-tauri/src/*.rs`     | Single-purpose modules (`settings`, `actions`, `overlay`, `tray`, `clipboard`, `input`, `llm_client`, `portable`, `utils`, ...) declared in `lib.rs` |

New code: stateful and long-lived goes in a manager; a frontend entry point goes in `commands/`; anything platform-only goes in its own file or `cfg` block.

## Tauri commands and bindings

- A command is `#[tauri::command]` + `#[specta::specta]` (`src-tauri/src/commands/history.rs`), then added to `collect_commands![...]` in `src-tauri/src/lib.rs` (~line 653). A command missing from that list is not callable from the frontend.
- `src/bindings.ts` is generated by tauri-specta and only written in debug builds (`#[cfg(debug_assertions)]` export, `lib.rs` ~778). Never hand-edit it; run `bun run tauri dev` and commit the diff.
- Argument/return types need `specta::Type` (`#[derive(Type)]` with serde). Exception: a few commands in `commands/mod.rs` and `shortcut/mod.rs` have `#[tauri::command]` without `specta` on the next line (they are not in the bindings list); do not copy that.
- Commands return `Result<T, String>` and convert with `.map_err(|e| e.to_string())` or `format!(...)` (about 170 occurrences). There is no shared error enum for commands.
- Managers are injected as `State<'_, Arc<XManager>>`; `AppHandle` is passed when settings or events are needed.

## Events to the frontend

- Typed events: `#[derive(Type, tauri_specta::Event)]` struct, registered in `collect_events![...]` (`lib.rs` ~772), emitted with the specta `Event` trait. Examples: `HistoryUpdatePayload` (`managers/history.rs:42`), `StreamTextEvent`, `StreamPhaseEvent` (`managers/transcription.rs`).
- Untyped events: `app.emit("name", payload)` with `tauri::Emitter`. Still common (`managers/model.rs`, `actions.rs`, `overlay.rs`, `shortcut/mod.rs`). Prefer the typed form for new events.

## State and concurrency

- Managers are built in `lib.rs` as `Arc<XManager>` and registered with `app_handle.manage(...)` (lines 214-217, again 920-921 for the headless path). Fetch with `app.state::<Arc<XManager>>()`.
- Shared interior state is `Arc<Mutex<T>>` with `std::sync::Mutex` (no `parking_lot`): `managers/audio.rs:377`, `managers/transcription.rs:249`, `managers/model.rs:546`. Also used outside managers (`audio_toolkit/audio/recorder.rs`, `paste_tx/macos.rs`). Locks are usually `.lock().unwrap()` (~118 sites). Plain flags use atomics (`lib.rs` `FILE_LOG_LEVEL`, `WEBVIEW_LOG_STREAMING`).

## Settings

- All settings live in `AppSettings` (`src-tauri/src/settings.rs`). Every field has `#[serde(default = "default_xxx")]` backed by a `fn default_xxx()`, so old stores still load (comment at line ~372). Add the field and its default fn together.
- Read with `get_settings(&app)`, write with `write_settings(&app, settings)`; both go through `tauri-plugin-store` at `portable::store_path(SETTINGS_STORE_PATH)` (`settings_store.json`). Use `portable::app_data_dir`, not a raw Tauri path, for app data.
- Setting-change commands live in `shortcut/mod.rs` (`change_*_setting`) and `commands/`; they mutate via `get_settings`/`write_settings`.

## Environment flags

- Name them `TYPEVOCAL_*`. Boolean flags use `utils::env_flag_enabled(name)` (`src-tauri/src/utils.rs:162`; re-exported from `lib.rs`): unset, empty, `0`, `false`, `no`, `off` are false.
- Exceptions that read the var directly: `TYPEVOCAL_METAL_RESIDENCY` (`== "1"`, `lib.rs:632`), `TYPEVOCAL_DEBUG_MIC_READY_DELAY_MS` (value), worker vars (`TYPEVOCAL_TRANSCRIBE_WORKER_*`, `TYPEVOCAL_WORKER_FAULT*`, fault injection in `worker.rs`).

## Errors and logging

- Two styles coexist. Managers and `audio_toolkit` use `anyhow::Result` / `anyhow!` (11 files, e.g. `managers/history.rs:1`). Command boundaries convert to `String`. `engine_supervisor` has its own `EngineError` enum (`supervisor.rs:138`). No `thiserror`.
- Log with the `log` crate (`info!`/`warn!`/`error!`/`debug!`/`trace!`, imported or as `log::...`); `tauri-plugin-log` is the sink (`lib.rs` ~798). Never use `println!`/`dbg!` for diagnostics.
- `eprintln!` is the exception, not the rule (15 uses): the headless CLI path in `lib.rs` (user-facing `error: ...`), `portable.rs` (before logging exists), and `engine_supervisor/worker.rs`.
- Avoid `unwrap()` on fallible I/O in production paths; `expect` is used for startup invariants (e.g. bindings export in `lib.rs`).

## Platform-specific code

- Use `#[cfg(target_os = "...")]` blocks inline for small differences (`lib.rs`, `overlay.rs`, `clipboard.rs` are heaviest), and a per-OS file selected in `mod.rs` for large ones (`paste_tx/`, `swift/` for Apple Intelligence).
- Platform crates go under `[target.'cfg(...)'.dependencies]` in `src-tauri/Cargo.toml` (windows, macos, linux, unix). `transcribe-cpp` GPU features differ per target there; keep them in sync.
- Code that is meaningful on one OS must still compile on the others (stub or `cfg`'d call sites).

## Worker process boundary

- All `transcribe_cpp` native work (backend init, device listing, model load, inference, streaming) runs only in the child process in `engine_supervisor/worker.rs`. Everything else talks to it via `EngineSupervisor` (`managers/transcription.rs:247`).
- `managers/transcription.rs` and `catalog/` import `transcribe_cpp` for option/result types only; do not call model or backend functions there.
- `main.rs` checks `is_worker_invocation()` before CLI parsing, Tauri, or single-instance. The worker must not initialise Tauri or write to stdout (stdout carries the framed protocol; log to stderr).
- Changing the wire format means editing `protocol.rs` on both sides together.

## History database

- SQLite via `rusqlite` (bundled) + `rusqlite_migration`. Migrations are the ordered `M::up(...)` list at the top of `src-tauri/src/managers/history.rs` (~line 13). Append only; never edit a shipped migration. The legacy `tauri-plugin-sql` table is converted by `migrate_from_tauri_plugin_sql`.

## Tests, formatting, linting

- Unit tests are inline `#[cfg(test)] mod tests` in the file under test (36 files), or a sibling `tests.rs` (`audio/recorder/tests.rs`, `model/download/tests.rs`). Integration tests: `src-tauri/tests/` (only `build_rs_rebrand.rs`).
- Run `cd src-tauri && cargo test` (CI: `.github/workflows/test.yml`). Worker tests that need a real model are env-gated (`TYPEVOCAL_TEST_MODEL`, `TYPEVOCAL_TEST_WAV`; see `supervisor.rs` ~1481).
- Format with `cargo fmt` (`src-tauri/rustfmt.toml` sets only `edition = "2021"`); `bun run format` runs it too.
- Clippy is not run in CI (no workflow invokes it); run `cargo clippy` yourself before committing.
